凭证工作台 0.5.1 · Windows x64 测试包

适用：Windows 10 / Windows 11 64 位，使用 CPU，无需独立显卡。

开始使用
1. 将整个 ZIP 解压到一个目录，不能直接在压缩包中运行。
2. 双击“启动凭证工作台.cmd”。请保留服务窗口，浏览器会自动打开。
3. 选择资料文件夹和明细账，默认第一个工作表，也可以指定工作表。
4. 设置“并行线程数”：默认 1，可手动选择 1–10；设置会保存，任务运行时不能修改。重试使用原任务的线程数。
5. 方向识别默认关闭，可以直接生成；也可以自行旋转图片。
6. 如启用标题方向识别，勾选表示同意旁边的免责声明。识别完成后，人工检查、按需修正并确认本次输出的每张图片，再生成 PDF。

通用 PDF 合并
1. 左侧选择“通用 PDF 合并”，选择本地资料文件夹；不需要明细账或OCR。
2. 指定合并层级：0递归合成一份；1每个直接子文件夹一份；2按第二层分组，最多32层。浅层文件会另列组。
3. 选择输出目录，留空默认在资料目录同级建立“资料名-合并PDF”。嵌套输出目录和本程序记录目录自动排除。
4. 可排除相对路径文件/目录，或使用 *、?、** 规则；每行一条。默认 **/indexImg/** 可以修改或清空。排除预览按实际命中项显示，不统计被排除目录内部文件。
5. 扫描后核对分组、页数、输出名、排除规则；可拖动或上下移动文件，更改输出名称后点击“保存顺序与名称”。选择要生成的有效组，再确认生成。
6. 每份源PDF内页序、页尺寸与旋转保持；不添加页眉页脚、封面或分隔页。通用记录可查看、下载报告、取消和按原计划重试。
7. 仅支持普通静态PDF；加密、表单、签名、图层等不支持结构会明确报错。书签与文档级元数据不承诺保留，不保持PDF/A等认证。仅支持真实本地磁盘，不跟随符号链接、联接或云占位文件，不支持UNC/映射网络盘。

并行处理
· 方向识别按图片并行，PDF 生成按凭证或通用分组并行；每份 PDF 内部的页序不变。
· 同一时刻只运行一个任务。所选线程数是并行上限，项目数量较少时实际工作线程也会减少。
· 更多线程通常占用更多 CPU 和内存，不保证按线程数成倍提速。可先以较少线程试用，再按电脑运行情况调整。
· 设置保存在程序数据目录，重启保留；修改设置不改变已有任务及其重试的线程数。

文件与退出
· 处理记录默认保存在 %LOCALAPPDATA%\VoucherWorkbench。升级时解压新包，保留这个目录即可继续使用原记录。
· 凭证PDF输出到原分项同级的“分项-PDF”目录，通用模式输出到指定目录；原件不改动，不添加页眉页脚。
· 每份 PDF 的 manifest.json 处理记录保存在上述程序数据目录的 outputs 子目录，不再新建在 PDF 旁。它保存来源、页码、旋转/复核和校验值，用于复用、恢复与防止误覆盖；交付 PDF 不必附带它，仍可在界面下载处理报告。
· 再次生成或复用旧版 PDF 时，工具核验旧旁置记录，复制核验到数据目录后才移除旁置文件；异常记录保留并提示。已有历史归档不批量搬迁，旧 PDF 仍可保留在输出目录 .history 中。
· 备份或换电脑时请保留整个数据目录。仅复制 PDF 或清空记录不影响阅读，但缺少可验证的记录时工具不会自动复用或覆盖已有 PDF。命令行 --state-dir 可指定其他数据目录，不会自动搬迁原记录。
· 关闭网页不会退出服务。结束使用时在服务窗口按 Ctrl+C，等待当前任务停止后关闭窗口。
· 再次双击启动入口会重新打开已有工作台，原任务继续；原服务仍在启动时会短暂等待，正常重复启动不报故障。
· 解压目录和资料路径可以包含中文及空格；不需要把资料放进程序目录。

启动遇到问题
· 升级前：先在旧版服务窗口等待任务完成并按Ctrl+C退出，再解压启动新版；不要直接清空处理记录。
· 旧版或无法联系的实例占锁：按中文提示切回原服务窗口退出后重试；程序不会自动结束旧进程或删除锁文件，也不会改用新的记录目录。
· 目录权限错误：检查当前账号对记录目录的读写权限、磁盘连接和安全软件限制。
· 指定端口占用：检查占用应用，或显式用 --port 0 选择可用端口。
· 浏览器打开失败：首次服务保持运行，检查HTTP/HTTPS默认应用，或复制原服务窗口完整网址手动打开。重复启动的错误窗口按任意键关闭后，修复设置再次双击；原任务继续。
· 真正启动失败时脚本保留窗口。反馈时描述中文原因，勿发送带 #token= 的完整网址。

运行依赖
应用不需要安装 Rust、Python、Office、Node.js 或 Docker。包中已附标题 OCR 模型和 Windows ONNX Runtime CPU 库，应用运行时不下载模型。
OCR 原生库还依赖 Microsoft Visual C++ 2019 或兼容更新版的 x64 运行库。若界面提示模型或 DLL 不可用，关闭识别的凭证合并及通用PDF模式仍可使用；需要识别时，从微软官方下载并安装 x64 运行库后重新启动：
https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist
运行库安装可能需要管理员权限，本工具不会自动安装系统组件。

识别局限
历史 3,270 张图片的 4 并行评估约需 23 分钟，该结果不是 0.5.1 的耗时承诺。本版可设置 1–10 线程，实际耗时随设备、资料及线程设置变化。
历史 39/3,270（1.19%）是模型未决率，不是准确率。识别可能误转、漏转或遇到混排；所有待输出图片均需人工核对并确认。
