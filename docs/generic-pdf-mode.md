# 通用 PDF 模式：使用与设计说明

> 本文仅记录 0.5.x `generic_pdf` 兼容入口。0.6.0 当前主流程以[批量合并规格](../openspec/specs/batch-merge/spec.md)和[README](../README.md)为准；新模式支持图片/PDF、可选索引与非阻塞核对。
以下是0.5.1 generic_pdf兼容入口的使用与设计说明，仅以[旧通用规格](../openspec/specs/generic-pdf/spec.md)约束该入口；当前0.6.0默认流程以[批量合并规格](../openspec/specs/batch-merge/spec.md)为准。API字段由[API文档](../app/API.md)维护，当前Windows构建、发布及客户验收统一见[发行记录](windows-release.md)。

## 操作流程

1. 选择“通用PDF合并”，填写本地资料根目录、合并层级和输出目录；不需要明细账或OCR。
2. 扫描期间显示忙碌，完成后查看每组来源、总页数、空目录、排除命中和错误。扫描一次返回完整预览；生成阶段提供进度及取消。
3. 按文件/目录相对路径或glob排除，选择自动顺序后重新扫描；也可在组内上移/下移并编辑输出名。
4. 保存手动草稿得到新的不可变计划，核对交付清单并选择可生成组。空组、坏PDF或名称冲突就地显示，不能强制绕过。
5. 生成时共用全局1–10线程，各组并行、组内顺序固定。可以取消或按原任务重试。
6. 从任务结果下载PDF/报告或打开登记输出目录。历史报告保留原配置，不能把更新后的成品冒充旧任务下载。

普通PDF合并无需OCR免责声明。扫描发现不支持的PDF结构时，提供未加密普通静态副本或明确排除再重扫；正常组可单独生成。

## 层级示例

```text
资料/
  总说明.pdf (2页)
  A/
    01.pdf (1页)
    02.pdf (3页)
    X/
      10.pdf (2页)
  B/
    03.pdf (1页)
```

| 选择层级 | 预览交付 |
| --- | --- |
| 0（默认） | 资料.pdf，共9页 |
| 1 | 资料.pdf（浅层2页）、A.pdf（6页）、B.pdf（1页） |
| 2 | 资料.pdf（浅层2页）、A.pdf（浅层4页）、A__X.pdf（2页）、B.pdf（浅层1页） |

深度是分组位置，扫描仍递归。浅层组防止根目录或中间目录的PDF被遗漏；详见有效规格的“层级与浅层文件唯一归属”。

## 默认配置与提示

默认输出是输入同级“根目录名-合并PDF”，组内相对路径自然升序。用户可以选择时间排序，或保存完整手动排列。更换输入、层级、输出、排除或自动排序后重新扫描；重新扫描不自动继承旧手动顺序。

默认排除 `**/indexImg/**`，规则显示可编辑；`index.html`等非PDF不会参与。排除规则示例：`草稿.pdf` 只匹配根直属文件，`**/草稿.pdf` 匹配任意层级，`A/*.pdf` 匹配A直属PDF，`草稿/**` 排除整个子树。目录被排除后不读取内部内容，因此预览不会编造其文件或页数。

预览中自动排除的当前输出子树与实际处理记录目录不能取消。输出与输入相同会拒绝；输出在输入内时重跑不读回成品。遇到同名未知PDF、外部修改、其他模式输出或名称冲突，请改名或换目录；程序不提供强制覆盖。

本轮只支持普通静态PDF和真实本地磁盘。网络共享/映射盘、符号链接/联接、占位文件、表单/脚本/签名/附件、可选图层、色彩输出意图、相对链接及文档内跳转等边界，以有效规格的支持清单为准；不承诺PDF/A、PDF/UA或文档级认证/标签继承。文件名保留原Unicode规范形，不宣称完整NFC或Windows语言折叠支持。

## 实现衔接

`app/src/generic.rs` 负责静态PDF扫描、分组、预览、不可变顺序保存、组装及通用路由。计划放在 `state-dir/generic-plans`；`jobs.rs` 共用任务、互斥和线程快照，以 `kind=generic_generate` 分派通用任务。通用结果中的兼容字段 `voucher_id` 表示组ID，实际manifest没有金融字段。

PDF组装复用现有页面导入；`pdf.rs` 的事务记录按manifest类型泛型化，凭证入口仍保留原包装函数及旧事务测试。输出PDF与临时PDF同盘提交，state-dir集中保存manifest/事务/新历史manifest，输出 `.history` 只保存历史PDF。

任务开始冻结自己的 `generic-plan.json`，提交每组后冻结manifest。报告、下载通过任务快照定位，输出下载重新核验哈希；保存新顺序不改写旧任务。来源扫描及生成前后核验路径、大小、修改时间、SHA256。更多线程只提高组间并行，不能保证等比例加速。

## 验证与剩余验收

只用代码生成的合成PDF验证，不把业务资料、日志、预览或运行状态纳入公开仓库/CI。`app/tests/generic.rs` 覆盖分组页数守恒、排除命中、嵌套输出、自然/时间/手动排序、名称冲突、1/10线程组装、页尺寸/旋转、不可变报告、归档/复用/未知及跨模式输出保护、同大小同时间内容变化、坏/加密/表单/跳转/图层/色彩意图/附件/相对链接、严格页树计数、取消及链接/API边界。共享PDF事务与既有凭证回归另行保留。

本机通过的自动化与CI/Windows客户实测必须分开记录。Windows中文/空格/长路径、目录联接/不可写目录以及实际客户资料仍需在对应环境验收；发布通过不代表客户Windows10已经完成真实双击与浏览器复测。
