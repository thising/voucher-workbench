# PDF工作台

**PDF工作台 0.6.0** 是在本机独立窗口运行的图片与 PDF 批量整理工具，采用 Tauri＋Rust，不需要外部浏览器、Office、Python、Node 或 Docker。资料、图片方向识别和处理记录均在本机处理，运行不使用 CDN。

当前有效依据只有[批量合并规格](openspec/specs/batch-merge/spec.md)及[桌面与 Windows 发行规格](openspec/specs/windows-distribution/spec.md)；旧凭证、旧通用 PDF 规格仅用于 0.5.x 记录与接口兼容。当前发行基线为 **0.6.0 Windows 10/11 x64**，构建结果、附件及校验值统一见[发行验收记录](docs/windows-release.md)。客户 Windows 10 的实际双击、组件安装、单位策略及真实资料验收单独记录，不能由本机验证或 CI 代替。

## 使用流程

界面分为“准备资料”“预处理”“执行合并”三个板块。

1. **准备资料**：选择目标文件夹后自动获取实际层级。默认“当前文件夹”将目标目录及全部子目录中的文件合并为一份；选择其他级别时，每个对应目录各生成一份，其上层直属文件另列，不遗漏。展开“查看待合并目录”可看每组候选文件数、待合并总数及空目录数；页数和文件错误在正式扫描后确定，空目录不生成 PDF。排除规则默认折叠，一行一条，支持 `#` 注释及 `*`、`?`、`**`；无效行忽略并在日志中提示。

    需要重命名时开启开关，选择 XLS/XLSX、工作表、表头行、“文件夹名称索引”和“重命名文件名”两列。默认首张工作表，可手动改选；索引表只用于命名，不作为 PDF 正文。默认**拼接“文件夹名-列内容”**，也可独立使用列内容；同索引固定取原表第一条，未匹配或首条名称为空时使用目录名。预览可逐行改名，同批重名须先修正。最后点击“扫描资料”，扫描期间显示真实进度、耗时并可取消。

2. **预处理**：扫描成功后出现三栏。左栏是合并文件夹、输出名和具体问题；中栏是文件顺序，可按文件名自然顺序、修改时间、前缀或后缀排序，也可拖动左侧手柄、置顶、上下移，或从本次合并移除/撤销移除；右栏预览并旋转。PDF 默认旋转当前页，也可选择整份；图片支持手动旋转。调整自动保存，改名或移除后重算页数和当前错误，原文件不改、不删。

    “自动调整图片方向”是可选步骤：阅读使用须知并勾选同意后才开始，仅处理图片，默认 4 线程，可选 1–10。**只对实际变角的图片标色并列出前后角度**，例如 0°→90°、90°→0°；未变、保留人工角度、未决和识别失败不标自动调整色，方向详情也不逐项列出，汇总会保留相应数量。PDF 不自动识别，可按页或整份手动旋转。自动识别可能误转、漏转，未识别、取消识别或未全部核对均不阻止合并；真实来源损坏等错误仍须处理。

3. **执行合并**：在独立的“执行合并”板块选择输出位置，默认目标目录同级“目录名-PDF”，核对份数、页数、名称与方向提醒。合并默认 4 线程，可选 1–10；每组一份，按当前顺序生成，不加封面、页眉、页脚、分隔页或新页码。

    输出目录已有同名普通文件时，运行到该项才询问**跳过、覆盖或取消任务**，可将跳过/覆盖应用于本批次后续同名项。**覆盖直接替换，不留备份，无法恢复**；取消不撤销此前已经完成的覆盖。跳过项不计成功页数，不将已有文件当作本次新成品下载。任务结束可保存报告/PDF、打开输出目录；重试保持原计划与线程，但重新询问同名处理，不继承“应用本批次”。

支持 JPG/JPEG、PNG、BMP、静态 WebP、单页 TIFF 及受支持的静态 PDF。图片先应用 EXIF，再生成 A4 横/纵页面，等比居中、不裁切；源 PDF 保留页尺寸、原有旋转与内部页序，再叠加人工角度。签名 PDF 可按静态页面合并，保留可靠的可见签章外观，**不验证、不保留原数字签名验证能力**，原件不变；旧版签名错误计划须重新扫描。加密、普通交互表单、脚本、附件或无法可靠保留签章外观等结构仍会明确报错。不跟随符号链接、目录联接、未下载云占位或网络盘，完整边界见有效规格。

## Windows 启动与升级

便携版需**完整解压**后双击 `PDF工作台.exe`，安装版运行文件名以 `-setup.exe` 结尾的安装包，再用“PDF工作台”快捷方式。重复启动会唤回原窗口，已有任务继续。WebView2 是独立窗口运行组件：已有则直接使用；缺少时按提示安装，离线电脑使用单独提供的微软 x64 离线运行时。具体版本、体积及 SHA256 见发行记录，组件不嵌入每次主包更新。

升级请按以下顺序保留记录：

1. 正常退出旧版，等待任务及另存操作结束；0.5.x 浏览器版应在原服务窗口按 Ctrl+C 退出。新版不会强杀旧进程、删除锁文件或换目录绕过占用。
2. 在资源管理器或“运行”中打开 `%LOCALAPPDATA%\VoucherWorkbench`，将**整个记录目录复制到另一位置备份**；若原来指定了自定义记录目录，备份并继续使用该目录。不要只留输出 PDF 或单个 JSON。
3. 将新版完整解压到新文件夹，或运行新版安装包，用同一 Windows 用户启动。无需清空记录目录、逐项搬迁或修改历史 JSON。
4. 打开“处理记录”检查原历史和最新计划，核对文件顺序、逐页角度及线程偏好，再试一小批资料。旧程序目录与记录备份先保留。

默认记录目录继续使用 `%LOCALAPPDATA%\VoucherWorkbench`。新批量识别/合并偏好分别保存，默认均为 4；旧版 `settings.json` 及复核结果保持原值，旧默认 1 线程不改写。同一记录目录只运行一个服务、同时处理一个任务；有任务或另存操作时关闭窗口，可选择继续处理或“安全停止并退出”，程序会等待安全收尾。

PDF 旁不新建 `manifest.json`。来源、页码、角度、命名及输出校验记录保存在记录目录的 `outputs/<输出路径摘要>/`，另有任务报告和计划。阅读/交付 PDF 不需要这些文件，但升级、备份或换电脑应保留完整记录。**处理记录不是旧 PDF 备份，不能恢复已经直接覆盖的文件**；既有历史归档不会自动清理。

## 常见问题与试用反馈

- **缺少 WebView2／OCR 组件**：先按随包说明补齐对应组件；OCR 不可用时仍能手动整理和合并，不必安装开发环境。
- **提示已有实例或记录被占用**：切回原窗口，正常退出后重试；不要强删锁文件。若找不到原进程，保留完整提示反馈。
- **文件数与预期不同／某组无法合并**：查看实际合并级别、排除规则和分类日志。初始化显示候选文件数，扫描才校验页数；坏文件可明确移除后合并其他来源，修复后也可重新扫描。
- **同名弹窗等待选择**：点击跳过、覆盖或取消任务；Esc 不会取消或隐藏待决任务。同批目录之间重名仍须改名，目录/链接/输入原件不能经覆盖按钮绕过保护。
- **升级后找不到历史**：确认使用相同 Windows 用户和原记录目录，不要先清空或新建记录目录。处理记录、输出 PDF 和源资料是不同内容。

试用反馈请提供：版本与包校验值、Windows 版本、便携/安装版、操作步骤、预期与实际结果、发生时间、文件/页数及错误提示；方向问题另说明自动/手动、线程数和前后角度。可附脱敏截图、报告摘要或可公开的最小样本。不要发送业务原件、完整记录目录、会话链接或带 `#token=` 的内容。客户 Windows 10 的双击启动、WebView2 安装、记录保留及真实成品检查仍须单独确认。

## 开发与验证

Rust 版本及依赖固定在[Windows依赖清单](app/distribution/windows-dependencies.json)、`app/Cargo.lock` 和 `app/desktop/Cargo.lock`。桌面开发另需对应平台的 Tauri 原生构建依赖；Node 仅用于固定版本的构建 CLI，不随客户包发布。

```sh
# 核心检查
sh app/tools/cargo-local.sh test --locked
sh app/tools/cargo-local.sh clippy --locked --all-targets -- -D warnings

# 本机独立窗口（另需标题模型/ONNX Runtime，缺少时仍可手工合并）
sh app/tools/cargo-local.sh run --locked --manifest-path desktop/Cargo.toml -- --state-dir /absolute/path/to/test-state --model /absolute/path/to/title-ocr --runtime /absolute/path/to/libonnxruntime.dylib

# 浏览器仅作为开发诊断入口
sh app/tools/dev.sh
```

工作区脚本优先使用 `.local` 隔离工具链，没有时使用本机 Cargo。模型下载和固定校验见[模型说明](app/models/README.md)。本地 HTTP 仅监听 `127.0.0.1`，API 使用会话认证与来源校验；桌面原生文件选择/保存仅授予本窗口的实际来源。认证链接不写入普通发现文件。

Windows 构建与验收：

```powershell
pwsh -File app/tools/build-windows-desktop.ps1
```

GitHub CI 流程配置为检查 Rust 核心、桌面壳、便携包和安装包，并实际启动 Tauri 窗口检查交互；测试使用合成资料，不发布业务数据。每轮是否通过以发行记录为准；CI 不能替代客户 Windows 10 的真实双击、WebView2 安装与单位安全策略验收。
